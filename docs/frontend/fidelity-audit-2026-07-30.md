# DESIGN-FIDELITY BRIEF — apps/web-v2 vs the approved export
*Synthesis of the per-screen audit, the shell/chrome code audit and the reuse audit. No files were changed.*

---

## 1. VERDICT

web-v2 is **structurally honest and visually adrift**. Nothing in it invents backend logic, nearly every gap is either an accurately documented `CONTRACT GAP` or a thin fixture, and the token layer landed cleanly — but a person opening the app next to the export would not call it the same product, because three root causes account for roughly 90% of the divergences:

1. **There is no full-height pane architecture.** The design roots at `height:100vh;overflow:hidden` and repeats `height:100%;overflow:auto;padding:28px 32px` eight times; the app roots at `min-h-screen` with `<main className="mx-auto min-w-0 max-w-720 flex-1 p-9">` and page-scrolls everywhere. A grep for `overflow-y-auto|min-h-0|h-dvh` across `src/` returns exactly one hit outside `Card` (`Sidebar.tsx:74`, solved privately). This single fact produces the blocking Review failure (3276px tall against the design's one 1000px frame), the upload/processing/session centring failures, the scroll-away of the order strip and its counts, and — through the `mx-auto`-on-a-flex-item bug — the queue's 670px column where 860px was asked for. **One file, `apps/web-v2/src/app/rootRoute.tsx:47,51`, is the proximate cause of two blocking findings and a dozen majors.**
2. **Fixture thinness, and two hand-maintained copies of the demo order.** The queue's four bands are all empty, the lifecycle board is a second unrelated order list that contradicts `/api/queue/next` about DEMO-0001, the sign-off's thirteen lines are invented rather than the product's canonical list, the pipeline is 38 pages where the design is 64, and `stages[signoff].phase:"done"` sits beside `signed_by:null`. Much of what reads as missing markup is missing data. Judgement is degraded until this is fixed: the next audit will re-report the same absences as layout defects.
3. **A built-and-bypassed component layer.** 14 shared components exist with zero production call sites (`entities/field/*` ×7, `shared/ui/{ClaimVsEvidence,RequiredComment,DestructiveConfirm,Checkbox,Tooltip}`, `entities/order/StageList`, `entities/rule/ProvenanceBadge`) while `features/review/` re-implements all of them — and the duplicates are the ones that drifted (the *dead* `DecisionBar` carries the design's exact button copy; the live `DecisionActions` does not). This is the four-near-identical-row-renderers failure HANDOFF §1 names, already recurred at component-layer scale, and `knip` is not catching it because `.stories.tsx` counts as usage.

Secondary, cheap, and large in count: copy drift (load-bearing design sentences paraphrased into weaker ones) and two **local-preview toggles shipped into production screens** that let a user repaint a server verdict — the most serious rule violation in the set, and trivially removable.

## 3. BLOCKING DIVERGENCES

Six items, deduplicated to the thing that owns them.

**B1 — No fixed-height frame. Owner: `apps/web-v2/src/app/rootRoute.tsx:47` (+ the `Pane` primitive that does not exist).**
`min-h-screen` on the flex row with `sticky top-0 h-screen overflow-y-auto` on the aside and a non-sticky OrderStrip, against the design's `display:flex;height:100vh;overflow:hidden` with the header `flex:0 0 auto` and only the sidebar's nav body scrolling. Consequences: `design-review.png` is one 1000px frame, `app-review.png` is 3276px with the sidebar terminating over blank ground; the order ref, four counts and stamp scroll off every long screen, falsifying `OrderCounts.tsx:54-57`'s own stated reason for existing; upload, processing, session and delivered cannot centre; completeness' order context scrolls away on a long gap list. **9 call sites.** *(Two agents disagree on where the app's sidebar fill stops — ~610px vs ~1000px. Same defect, different capture; immaterial.)*

**B2 — Auto inline margins on a flex item cancel `align-self:stretch`. Owner: `rootRoute.tsx:51`.**
`<main className="mx-auto min-w-0 max-w-720 flex-1 p-9">` inside `<div className="flex min-w-0 flex-1 flex-col">` sizes `main` shrink-to-fit, so QueueScreen's `max-w-430` (860px) only ever gets ~670px — 22% narrower than drawn — squeezing every card, the paragraph and the toggle, and forcing the Next-up button group against the order line. Overview only looks right because its 7-column max-content exceeds the pane. Fix: keep `main` full-width and centre an inner wrapper. Also note `max-w-720` = **1440px** on the 2px base, and a viewport-width guard will not catch this — the container is the binding constraint. Affects queue, upload, clients, session, profile.

**B3 — The chrome is drawn to unauthenticated viewers. Owners: `AppChrome.tsx:63`, `OrderStrip.tsx:52` (both gate only on `/blind`).**
`app-signin.png` shows the full 232px sidebar with every ADMIN door and a top strip reading "L. Vance / ADMIN" for a person who is not signed in; the design is a bare centred card (`showChrome = !(isSignin||isSession)`). Same path affects `/session`. Fix with the `chromeless()` predicate — encoding that `/blind` additionally suppresses the preference and attention fetches, while `/signin` needs no such rule.

**B4 — Review renders every field value twice in one pane. Owner: `features/review/FieldList.tsx:63-73` (delete).**
A `SETTLED 15 — look, do not re-decide` card lists all 15 non-queued fields, and `CallBackSheet.tsx` re-renders the identical 15 rows ~900px below. The pane is twice the design's height and the 6 decisions that need a person sit sandwiched between two copies of the same 21 facts. It also mixes `auto_confirmed` fields — never anybody's decision — into a surface headed "Decision queue". `FieldList.tsx:11-15` names the risk and then does it. The design is explicit: "The dock holds ONLY the card you are working."

**B5 — The upload screen is the wrong screen. Owner: `features/ingest/IngestScreen.tsx:104-141`.**
The design's body is four blocks — file receipt card, a 2-col CLIENT card grid, a 3-col six-card PRODUCT grid, `Continue to sign-off →` — with exactly one text input on the whole screen (the conditional Update prior-effective-date box). The app renders one invented three-clause eyebrow over five bare text inputs and an `upload the package` button. No file card, no client grid, no product grid, no forward link to Step 2.

**B6 — The client picker is a free-text field, and the gap note justifying it is factually wrong. Owner: `features/ingest/orderFields.ts:4` + `OrderForm.tsx:22-32`.**
`GET /api/clients` already exists on the wire (`ClientsResponse`, served at `packages/mocks/src/workspace.ts:305`, returning `{id,code,name}`), so the `CONTRACT GAP` at `IngestScreen.tsx:38-44` ("Nothing lists either") is false for clients and should be deleted. A typed client id is strictly worse than a picker: a mistype resolves the wrong sign-off list — which is the one thing intake decides.
